# Qwen Web — быстрый старт (Windows)

**Язык:** [English](QWEN.md) | **Русский**

**Нужен только Qwen в терминале? Начните здесь.** Для этого не требуется настраивать ChatGPT, HDE, Gemini, DeepSeek или основное расширение CWA.

В этой инструкции используется **Qwen SDK через браузер**: Python отправляет сообщения через **отдельное расширение Chrome для Qwen** в вашу авторизованную сессию [chat.qwen.ai](https://chat.qwen.ai/). Вкладка может оставаться фоновой. Это не официальный API Qwen и не полностью автономный HTTP-клиент.

**Что понадобится:** Windows, Python **3.10–3.14**, Git, Chrome и собственный аккаунт Qwen. Провайдер пока **экспериментальный**: текстовые диалоги и сетевой streaming успешно проверены с установленным SDK на Windows, но поведение сайта может измениться.

## Первоначальная настройка (один раз)

### 1. Скачайте проект и установите пакет

Откройте PowerShell:

```powershell
git clone https://github.com/kymuco/chatgpt-web-adapter.git
cd chatgpt-web-adapter
python -m pip install -e .
```

Репозиторий нужен потому, что `qwen_sdk.py` — **готовый CLI-скрипт в исходниках**, а не отдельная команда `qwen`, которую устанавливает `pip`. Устанавливайте пакет и запускайте чат из одного и того же окружения Python. Авторизация ChatGPT и настройка обычного расширения CWA **не нужны**.

### 2. Создайте отдельное расширение Qwen

```powershell
python -m chatgpt_web_adapter.qwen_native
```

Команда подготовит расширение и выведет путь к его папке. При стандартной установке Windows он такой:

```text
%LOCALAPPDATA%\chatgpt-web-adapter\qwen-native\extension
```

В Chrome:

1. Откройте `chrome://extensions` и включите **Режим разработчика** (*Developer mode*).
2. Нажмите **Загрузить распакованное расширение** (*Load unpacked*) и выберите папку расширения Qwen.
3. Скопируйте ID установленного расширения **Qwen Web Adapter (isolated)**.

**Важно:** это новое расширение для Qwen, а не существующее расширение ChatGPT/CWA. Не используйте ID расширения ChatGPT.

### 3. Подключите собственный Native Host Qwen

Замените `YOUR_QWEN_EXTENSION_ID` на настоящий ID из Chrome:

```powershell
python -m chatgpt_web_adapter.qwen_native --extension-id YOUR_QWEN_EXTENSION_ID
```

Затем на странице `chrome://extensions` **перезагрузите именно расширение Qwen**.

Так вы зарегистрируете отдельный Native Messaging Host `com.kymuco.qwen_web_adapter`. Рабочий хост ChatGPT/CWA `com.kymuco.chatgpt_web_adapter` не заменяется.

Откройте [chat.qwen.ai](https://chat.qwen.ai/) в Chrome и войдите в свой аккаунт Qwen. **Для работы браузерного SDK Chrome должен оставаться запущенным.**

## Запустите чат в терминале одной командой

В PowerShell, находясь в папке `chatgpt-web-adapter`:

```powershell
python .\qwen_sdk.py --stream network
```

Это **наш настоящий интерактивный Qwen SDK CLI**: без тестовых запросов, вспомогательных проб и ручного копирования токенов.

Пример сеанса:

```text
Qwen SDK · transport=browser · /exit для выхода
Вы: привет
[Здесь появляется потоковый ответ Qwen]
Вы:
```

Введите вопрос и нажмите Enter. Ответ отображается по мере поступления фрагментов. Для выхода используйте `/exit`. В пределах одного запуска CLI следующие сообщения продолжают тот же диалог.

> **Почему `--stream network`?** По умолчанию CLI использует DOM-наблюдения (`dom`). В фоновой вкладке DOM может отобразить не весь текст, даже когда Qwen уже закончил генерацию. Сетевой поток (`network`) — предпочтительный путь, подтверждённый проверкой SDK на Windows. Однако ни один из режимов сам по себе не гарантирует каноническое, долговременное подтверждение состояния диалога на сайте.

## Повседневные команды того же CLI

Выполняйте команды **из корня репозитория**:

| Задача | Команда |
| --- | --- |
| **Открыть интерактивный чат** (рекомендуется) | `python .\qwen_sdk.py --stream network` |
| Отправить одно сообщение | `python .\qwen_sdk.py --stream network "Привет!"` |
| Продолжить существующий диалог | `python .\qwen_sdk.py --chat YOUR_CHAT_UUID --stream network` |
| Подключиться по URL диалога Qwen | `python .\qwen_sdk.py --chat "https://chat.qwen.ai/c/YOUR_CHAT_UUID" --stream network` |
| Подтвердить возраст, если Qwen этого требует | `python .\qwen_sdk.py --auto-confirm-age --birth-year YOUR_BIRTH_YEAR --stream network` |
| Явно вывести вкладку Qwen на передний план | `python .\qwen_sdk.py --foreground-tab --stream network` |

`YOUR_CHAT_UUID` — UUID из настоящей ссылки на диалог `chat.qwen.ai/c/...`. Вместо `YOUR_BIRTH_YEAR` укажите **свой реальный год рождения**. Эта опция не обходит возрастные ограничения сайта.

**Команды внутри интерактивного чата:**

- `/exit` или `/quit` — завершить работу CLI.
- `/retry` — **только** если Qwen явно сообщил о перегрузке (*busy/high-demand*) и доступна кнопка **Regenerate** («Повторить генерацию»). SDK один раз запускает повторную генерацию ответа **в том же чате**, а не отправляет второй экземпляр вашего запроса. Не используйте `/retry` вслепую после ошибки с неопределённым результатом отправки.

## Использование через Python вместо терминала

```python
from chatgpt_web_adapter.qwen_client import QwenClient

client = QwenClient(transport="browser")
first = client.send_text(
    "Привет!",
    on_token=lambda chunk: print(chunk, end="", flush=True),
)
print()

second = client.send_text(
    "А что я спросил сначала?",
    conversation=first.conversation,
)
print(second.text)
```

Если запускаете новый процесс Python, используйте `QwenClient.chat("YOUR_CHAT_UUID")` и передайте полученный объект через аргумент `conversation` в `send_text`.

## Решение проблем и ограничения

**Расширение недоступно:** убедитесь, что загрузили **папку Qwen**, зарегистрировали **его собственный** 32-символьный ID и перезагрузили расширение. Проверьте, что Chrome запущен и вы вошли в `chat.qwen.ai`.

**Не тот Python или не найден CLI:** из корня клонированного репозитория повторите `python -m pip install -e .` в том же окружении, из которого запускаете `python .\qwen_sdk.py`.

**Qwen сообщает о перегрузке:** используйте `/retry` только для последнего явно подтверждённого ответа *high-demand*. Если неизвестно, принял ли сайт отправленное сообщение, **сначала проверьте настоящий диалог**, не отправляйте текст повторно автоматически.

**Нужна работа вообще без браузера?** Есть отдельный экспериментальный режим `python .\qwen_sdk.py --transport http`, но успешная прямая генерация через Qwen Web HTTP **не подтверждена**. Сайт может возвращать HTML-страницу проверки вместо API-ответа. Рекомендуемый выше вариант требует Chrome.

**Что подтверждено:** текстовые сообщения через браузер, создание чата, продолжение разговора, сетевой поток ответа, подключение к существующему диалогу. **Что не заявлено как поддерживаемое:** изображения и файлы Qwen Web, выбор модели через браузерный SDK, автоматическое долговременное обновление HTTP-токена, каноническое подтверждение завершения, полноценная обработка выбора между двумя предложенными ответами.

Нужны все примеры Python/CLI, подробности ошибок и границы подтверждённых возможностей? Откройте **[полный справочник Qwen SDK (на английском)](docs/qwen.md)**. Почему используется отдельное расширение, объясняется в [инженерном документе об изоляции Qwen](docs/engineering/qwen_browser_isolation_plan.md).
