## Research / diagnostic lineage

Many files in this directory are named after PR8.x milestones, especially browser-authority/Sentinel characterization documents. They are intentionally retained because they record why particular safety, finality, retry, transport and browser-resource decisions exist.

Examples include:

- `browser_authority_*_pr8_8.md`;
- `temporary_chat_*_pr8_*.md`;
- `safe_browser_response_*_pr8_9.md`;
- `product_model_profile_*_pr8_10*.md`;
- `post_answer_tail_latency_pr8_11.md`;
- `normalized_activity_streaming_pr8_12.md`;
- older browserless feasibility/closure documents.

These are **reference/evidence documents**. Their historical wording may mention the milestone state at the time of the experiment. Current product claims are governed by:

1. [`../STATUS.md`](../STATUS.md);
2. [`../README.md`](../README.md);
3. [`architecture.md`](architecture.md);
4. [`../ROADMAP.md`](../ROADMAP.md);
5. the latest specific contract document for the surface in question.

## Documentation rule

When a new product-facing milestone changes a capability/support boundary:

- update current landing/status/architecture docs as needed;
- preserve the exact milestone evidence document;
- do not rewrite historical evidence to pretend it was written with later knowledge;
- clearly mark stronger/later contracts instead of silently changing history.

This repository intentionally favors traceable evidence over a perfectly flat documentation tree.
