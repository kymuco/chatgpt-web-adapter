# PR10.1 — Generated Artifact Observation and Explicit Download Handoff

_Status: bounded milestone complete — observation contract retained; download handoff unsupported on the proven product surface._

_Base content: post-PR10.0 `main`._

## Result

PR10.1 establishes a truthful product boundary for files generated by ChatGPT. The
milestone deliberately ends without an artifact download primitive because the
characterized product surfaces did not prove both:

1. a stable product-owned generated-artifact identity suitable for runtime use; and
2. a safe browser-owned resolution path from that identity to bytes without exposing
   capability-bearing locators as public evidence.

The frozen milestone status is:

```text
ARTIFACT_DOWNLOAD_HANDOFF_UNSUPPORTED_WITHOUT_STABLE_PRODUCT_IDENTITY
```

That status is a capability boundary, not a field on `ProductArtifactObservation`.
A syntactically valid point observation never grants download, local-path, overwrite,
retry, fallback, or canonical-finality authority.

```text
artifact observed
    != artifact locator exposed
    != download requested
    != destination authorized
    != overwrite authorized
    != canonical turn finality
```

## Existing artifact concepts remain separate

PR8.15 `ConversationArtifactManifest` describes local CWA conversation exports and
snapshots. PR9.2 remote-media download materializes caller-supplied input before an
upload/attach turn. Neither contract means "file generated by the ChatGPT product".

PR10.1 therefore keeps a distinct product observation rather than reusing those names
or authorities.

## Typed artifact point evidence

`ProductArtifactObservation` is a fail-closed evidence contract for an explicitly
identified product-generated artifact. It has phase `OBSERVED` and contains only:

```text
observation_id
artifact_id
filename                 optional basename only
media_type               optional MIME type
size_bytes               optional non-negative integer
download_available       boolean only
source_origin            product_message_metadata | product_content_part
sequence                  optional
observed_at_ms            optional
kind                      ARTIFACT (PR10.1-internal kind)
phase                     OBSERVED
```

The internal artifact kind is deliberately not added to the released PR9.3 public
`ProductObservationKind` enum or root exports. Authenticated characterization did not
justify widening that public capability surface.

## Identity rule

No synthetic artifact id is allowed. CWA does not infer artifact identity from:

- filename;
- message order;
- assistant prose;
- DOM position;
- URL similarity;
- tool name;
- local destination name.

A collector may materialize `ProductArtifactObservation` only from an explicit
artifact/file/asset identifier on an accepted structured product event. This model is
a contract boundary; the live characterization performed in PR10.1 did not prove a
stable current product source from which CWA should manufacture or infer such an id.

## Locator and privacy rule

Capability-bearing download locators stay inside the browser/product boundary.
`url`, `href`, `download_url`, `download_uri`, `signed_url`, credentials, cookies,
OAuth material, raw artifact bytes, raw DOM, and private reasoning are not eligible
for typed artifact observations.

The browser may reduce the *presence* of an explicit locator to
`download_available=true`, but never emits the locator value. The Python collector
fails closed if a locator or credential field appears on an artifact event at all.

## Runtime authority

Artifact observations are collected through the same runtime-owned observation gate
as PR9.3/PR10.0 evidence. A collector defect may increment dropped evidence but cannot
invalidate, replay, retry, or change canonical finality of the already delegated
product turn.

Artifact observation grants none of:

```text
download authority
filesystem write authority
destination selection authority
overwrite authority
automatic retry
fallback transport
```

PR10.1 installs no generated-artifact download/materialization path.

## No-write support proof

The outermost PR10 support RPC was extended compatibly with PR10.1 fields:

```text
generatedArtifactObservationSupported          true
generatedArtifactObservationSchemaVersion      1
explicitArtifactIdentityRequired               true
artifactLocatorExported                        false
artifactObservationGrantsDownloadAuthority     false
artifactObservationGrantsOverwriteAuthority    false
writePerformed                                 false
```

Older PR10.0 callers can ignore the additive fields. Characterization gates require
these safety claims before any bounded live observation.

## Authenticated characterization evidence

The historical generation gate spent one bounded product write to ask ChatGPT to
create the harmless probe file `cwa_pr10_1_probe.txt`. It performed no download and no
local write. All later topology/state probes were read-only.

The evidence chain is intentionally recorded because the unsupported result is itself
part of the milestone:

1. **Raw response / typed event path** — no explicit generated-artifact observation
   with stable product-owned identity was observed.
2. **Canonical conversation payload** — no probe-anchored artifact identity was
   exposed on the bounded structured payload path.
3. **Rendered filename surface** — the probe filename was present only in code/text
   echo candidates; this is not artifact identity.
4. **DOM/action topology** — bounded non-code and action-host scans found generic UI
   structure, not a product-owned artifact action or stable locator/identity surface.
5. **React fiber/application state** — artifact vocabulary and `attachments` plumbing
   were observed, but no stable identity field was proven.
6. **Targeted `attachments` subtree** — no identity/locator field names were found in
   the bounded subtree.
7. **Root-shape characterization** — twenty roots were null/undefined and exactly one
   non-empty `attachments` object was localized under a minified component's
   `update_queue` state.
8. **Root-key characterization** — that object had `type -> string`, two opaque-key
   arrays, and one opaque-key boolean. It was not a classic
   `<artifact-id> -> attachment-record` map; no record-like identity-key child was
   observed.
9. **Array-element v10 probe** — its one live attempt had no runtime conversation tab
   (`runtime_tab_present=false`) and therefore could not prove turn placement. This
   result is **inconclusive**, not negative, and is not used as evidence that the
   arrays lack artifact data.

The v6–v10 probes remain in-tree as bounded characterization evidence. PR10.1 does not
continue deeper into minified React/update-queue implementation details because such a
path would be unstable product reverse-engineering rather than a defensible SDK
contract.

## Frozen download handoff boundary

Actual generated-artifact download/materialization is intentionally unsupported in
this milestone.

The runtime must not:

- parse or reuse signed links from assistant prose;
- expose locator values merely because they were found inside product state;
- treat filename, DOM order, React position, or opaque implementation keys as
  product-owned identity;
- click a product download control implicitly;
- choose a local destination implicitly;
- overwrite an existing path implicitly;
- retry or fall back to another write/read path after failure;
- alter canonical turn finality because artifact materialization failed.

## Re-entry / graduation rule

A future milestone may reopen generated-artifact download only when authenticated live
evidence proves a stable product-owned identity **and** a safe browser-owned resolution
path against a non-guessed product contract.

Only then may an explicit handoff be designed. Such a handoff must require:

- an explicit caller download request;
- an explicit local destination;
- explicit overwrite authority when the destination already exists;
- no public export of signed/capability-bearing locators;
- exact final byte size and SHA-256 over materialized bytes;
- download failure remaining independent of canonical ChatGPT turn finality;
- no automatic write retry or fallback transport.

## Acceptance gates — final

PR10.1 is bounded complete when all of the following hold:

1. artifact observation requires explicit product identity;
2. filenames reject path components/traversal;
3. locator/credential-bearing events fail closed;
4. runtime preserves PR10.0 observations and canonical write authority;
5. browser characterization exports no locator values, raw private text, or raw
   internal state values;
6. download/local-write/click authority is absent from the artifact observation path;
7. the unsupported handoff status is explicit and separate from point evidence;
8. authenticated characterization is recorded without upgrading inconclusive probes
   into negative evidence;
9. no deeper minified-React reverse-engineering is required for milestone closure;
10. full supported CI, release build, and installed-wheel smoke are green on the exact
    branch head.
