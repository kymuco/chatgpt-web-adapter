# PR10.1 — Generated Artifact Observation and Explicit Download Handoff

_Status: working contract / live characterization pending_

_Base content: post-PR10.0 `main`._

## Goal

PR10.1 adds a truthful product boundary for files generated by ChatGPT. The milestone
must distinguish seeing a downloadable artifact from receiving permission to fetch
its bytes or write them to a local destination.

```text
artifact observed
    != artifact locator exposed
    != download requested
    != destination authorized
    != overwrite authorized
    != canonical turn finality
```

The first implementation slice intentionally proves artifact identity/metadata before
adding a download primitive. A download API designed around guessed URLs or DOM links
would violate the same evidence discipline established by PR10.0.

## Existing artifact concepts remain separate

PR8.15 `ConversationArtifactManifest` describes local CWA conversation exports and
snapshots. PR9.2 remote-media download materializes caller-supplied input before an
upload/attach turn. Neither contract means "file generated by the ChatGPT product".

PR10.1 therefore introduces a distinct product observation rather than reusing those
names or authorities.

## Typed artifact point evidence

`ProductArtifactObservation` is emitted only for explicit product-owned artifact/file/
asset identity. It is point evidence with phase `OBSERVED`.

Safe fields are bounded to:

```text
observation_id
artifact_id
filename                 optional basename only
media_type               optional MIME type
size_bytes               optional non-negative integer
download_available       boolean only
source_origin            product_message_metadata | product_content_part
sequence                  optional
observed_at_ms            optional
kind                      ARTIFACT (provisional PR10.1 kind)
phase                     OBSERVED
```

The provisional artifact kind is deliberately not added to the released PR9.3 public
`ProductObservationKind` enum or root exports before authenticated product evidence.

## Identity rule

No synthetic artifact id is allowed. CWA does not infer artifact identity from:

- filename;
- message order;
- assistant prose;
- a DOM link position;
- URL similarity;
- tool name;
- local destination name.

The browser overlay currently accepts only explicit artifact/file/asset identifiers in
bounded message metadata or structured content-part objects. String content parts are
not parsed for artifact identity.

## Locator and privacy rule

Capability-bearing download locators stay inside the browser/product boundary.
`url`, `href`, `download_url`, `download_uri`, `signed_url`, credentials, cookies,
OAuth material, raw artifact bytes, raw DOM, and private reasoning are not eligible
for typed artifact observations.

The browser may reduce the *presence* of an explicit locator to
`download_available=true`, but never emits the locator value. The Python collector
fails closed if a locator or credential field appears on an artifact event at all.

## Runtime authority

Artifact observations are collected through the same runtime-owned observation gate
as PR9.3/PR10.0 evidence. A collector defect may increment dropped evidence but cannot
invalidate, replay, retry, or change canonical finality of the already delegated
product turn.

Artifact observation grants none of:

```text
download authority
filesystem write authority
destination selection authority
overwrite authority
automatic retry
fallback transport
```

## No-write support proof

The existing outermost PR10 support RPC is extended compatibly with PR10.1 fields:

```text
generatedArtifactObservationSupported          true
generatedArtifactObservationSchemaVersion      1
explicitArtifactIdentityRequired               true
artifactLocatorExported                        false
artifactObservationGrantsDownloadAuthority     false
artifactObservationGrantsOverwriteAuthority    false
writePerformed                                 false
```

Older PR10.0 callers ignore the additive fields. PR10.1 live characterization requires
them before spending its one product-write budget.

## Authenticated live gate

`tools/pr10_1_artifact_live_gate.py` first performs the no-write support proof. Its
single allowed product write asks ChatGPT to create one tiny plain-text file named
`cwa_pr10_1_probe.txt` containing a fixed harmless marker.

The gate does **not** download the file. It reports only safe normalized events and
checks the existing canonical readback/finality, exact identity, no-retry, no-fallback,
and private-reasoning boundaries.

A live result with no explicit artifact observation is characterization evidence, not
permission to parse links from assistant text. The browser/product shape must then be
characterized more narrowly before expanding identity extraction.

## Download handoff graduation rule

Actual download/materialization is the second half of PR10.1 and is intentionally
blocked until authenticated evidence proves a stable product-owned artifact identity
plus a browser-owned resolution path that does not expose capability locators as
public evidence.

When implemented, the handoff must require an explicit caller request and explicit
local destination. It must not overwrite an existing path implicitly. Successful
materialization must return exact byte size and SHA-256 over the final local bytes.
Failure must not change the canonical finality of the ChatGPT turn and must not trigger
automatic retry/fallback.

## Initial acceptance gates

Before the first live generation probe:

1. artifact observation requires explicit product identity;
2. filenames reject path components/traversal;
3. locator/credential-bearing events fail closed;
4. runtime preserves PR10.0 observations and canonical write authority;
5. browser overlay exports no locator values or assistant text;
6. loaded extension proves additive PR10.1 support with zero writes;
7. live gate contains exactly one product-write path and no download/local-write path;
8. full supported CI and installed-wheel smoke are green on the exact head.

After live evidence, PR10.1 either implements the explicit download handoff against the
proven product shape or records the unsupported boundary without guessing around it.
