# Browserless ChatGPT HTTP SDK — experimental boundary

This is the **opt-in direct HTTP** client introduced in PR #212.
It is **not** the older `assemble_product_runtime(transport="browserless-request")`,
and it does not start Chrome, a browser tab or the Native Messaging host.
The implementation uses the existing CWA authenticated session, curl and
Node.js 24+; it relies on a changeable private ChatGPT web protocol.

## Python API

Use one consistent installed package or source checkout; do not mix
an editable install from another CWA branch with selected files copied here.

```python
from pathlib import Path
from chatgpt_web_adapter.browserless_http import BrowserlessHTTPClient

client = BrowserlessHTTPClient(auth_file=Path("auth_data.json"))

first = client.send(
    "Explain the design briefly.",
    model="gpt-6-instant",
    on_token=lambda token: print(token, end="", flush=True),
)
print()
print(first.conversation.conversation_id)

next_turn = client.send(
    "Now point out one limitation.",
    conversation=first.conversation.conversation_id,
)
print(next_turn.text)

# New, separate ephemeral conversation:
temporary = client.send("Hello.", temporary=True)

# Optional, explicitly selected local attachments:
response = client.send("Summarize these notes.", media=[Path("notes.md")])
```

`prepare_next_turn()` is optional one-use preparation. It is not a
background scheduler, and an expired preparation is regenerated by the
library. Inspect `client.last_timing` after a send to understand latency.

## Intended downstream integration (Codexia, HDE)

- Treat the client as a **transport**, not Work/admission/permission authority.
- Record the exact intent/Work binding before the possible external effect.
- Use server conversation/message identities and a read-only canonical history
  check when available. The requested model slug is not model-attestation.
- Do not assume a returned text stream proves canonical completion. A success
  with canonical IDs still needs the downstream application's admission policy.
- Never automatically resend after a timed-out, interrupted or otherwise
  ambiguous write. Missing history is not proof of non-submission.
- Keep credentials in `auth_data.json` outside version control. Do not print
  cookies, bearer tokens, protocol payloads or complete private documents as
  default progress output.
- Fail closed if the session expires, server challenge cannot be legitimately
  completed, or the pinned public module changes. No browser fallback.
- For downstream interactive E2E, report distinct, **sanitized** stages:
  preflight, claim/handoff committed, direct submit attempt, visible token
  stream (explicit opt-in), canonical readback, provider IDs verified,
  Work admission / yielded result. Do not report `submitted` as proven
  merely because a local function was called.

## Status of verified behavior

User-run continuous text conversations, ordinary and Temporary Chat, streaming
and more-than-one-hour session reuse have been reported on the separate PR #212
checkout. Earlier live notes also report single PNG/TXT uploads.

One Codexia delegated-Work E2E with three Markdown attachments was observed:
GPT-6 with requested `high` mapped to observed `extended`, streamed text,
verified exact assistant message readback and `CAPTURED_UNADMITTED`. This is
transport evidence, **not** Gen2 cognition admission or Work completion. It
does not prove general reliability across models, attachment formats, session
renewal or changing web-protocol revisions.

This module remains **experimental and explicitly opt-in**, even when included
in `main`. Existing browser-owned ChatGPT and isolated Qwen SDK behavior remain
the default; the HTTP client has no automatic browser fallback.

No live requests are made by the `test_browserless_http_client_contract.py`
regressions; they exercise the client boundary with a mocked underlying send.
